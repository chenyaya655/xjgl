# 25 生僻字全链路（二）：字体、检索与打印

> 对应代码：`src/Xjgl.Reporting/PrintFontRegistry.cs`、
> `src/Xjgl.Reporting/StudentPdfRenderer.cs`、
> `src/Xjgl.Domain.Shared/Text/RareCharacterText.cs`
> 对应测试：`test/Xjgl.Domain.Tests/Printing/StudentPdfRendererTests.cs`

## 25.1 要解决的问题

第 24 章把"字**存得对**"解决了。但用户看到的最后一环是**打印件** ——
而 PDF 里的中文不是"文本"，是**字形**。字体里没有这个码点的字形，渲染器只能给一个方块（□），
或者更糟：**静默丢字**，一列姓名里少一个字，肉眼很难发现。

生僻字在打印上有三个独立问题：

| 问题 | 表现 | 本章做法 |
|---|---|---|
| 主字体缺字形 | 方块 / 丢字 | 注册**备用字体族**，按 unicode-range 回落 |
| 备用字体也没有 | 还是方块 | **缺字形直接报错**，不出方块 |
| PDF 阅读器没装该字体 | 换台电脑就变样 | 字体必须**内嵌**进 PDF |

## 25.2 第一步：把"用哪个字体"收在一处

`PrintFontRegistry` 是唯一决定字体族的地方。这样做的理由很实际：
渲染库（本项目用 QuestPDF）**可能被换掉**，而"字体从哪来"这件事与渲染库无关。

```csharp
// 主字体：覆盖绝大多数汉字
// 备用字体：专门覆盖 CJK 扩展区（生僻字）
public static class PrintFontRegistry
{
    // 主字体族（可用配置覆盖，CI 的 Linux 镜像装 fonts-noto-cjk）
    public static string DefaultFontFamily =>
        Environment.GetEnvironmentVariable("XJGL_PRINT_FONT") ?? "Microsoft YaHei";

    // 生僻字字体族；**目录可配置**，仓库不分发字体文件（见 25.5）
    public static string? RareCharacterFontFamily { get; }
}
```

## 25.3 第二步：缺字形**直接报错**，不出方块

这是本仓库的一条硬约束，也是最容易做反的决定。两种常见做法都不对：

```csharp
// ❌ 做法一：让它画方块
//   用户看到一排 □□□，以为是字体没装，其实系统"什么都没说"
text.FontFamily(font);

// ❌ 做法二：静默跳过缺字形的字符
//   姓名"周𠮷"打成"周" —— 这是**改动了别人的名字**，比画方块严重得多
```

正确做法是**在渲染前检查**，缺字形就抛业务异常并把缺失的码点写进消息：

```csharp
// 打印前逐码点检查：当前字体链能不能覆盖
var missing = RareCharacterText.FindUncoveredCodePoints(text, fontChain);

if (missing.Count > 0)
{
    throw new BusinessException(XjglDomainErrorCodes.PrintFontMissingGlyph)
        .WithData("reason",
            $"字体缺少以下字形：{string.Join("、", missing.Select(FormatCodePoint))}。" +
            "请安装生僻字字体（Xjgl:Print:RareCharacterFontDirectory），" +
            "或核对原件后改用图片/其它方式出件。");
}
```

**为什么"报错"比"画方块"好**：
方块会被当成"打印机的问题"或"显示器的问题"，排查方向完全错；
而一句"字体缺少 U+20BB7 的字形"直接指向要装什么。

> ⚠ 顺带说明一个**没有采用**的方案：**"生僻字图片兜底"**（把缺字形的字预先转成图片贴进 PDF）。
> 它在代码里从未实现，方案文档早期只是提过一句，现已明确否掉。
> 理由：图片兜底会让"这一列到底是文字还是图"变得不确定（复制/检索都失效），
> 且真正的根因（字体没装）被永久掩盖。**用编码方式保证正确 + 字体覆盖码点**才是方向。

## 25.4 第三步：字体必须内嵌

这是 PDF 与"屏幕显示"最大的区别：PDF 是**自描述**的，但**不包含字体**时，
阅读器只能拿本机字体去凑 —— 换一台没装生僻字字体的电脑打开，就变回方块。

```csharp
// QuestPDF：FontManager 注册 + 渲染时要求内嵌
FontManager.RegisterFont(File.OpenRead(rareFontPath));

// 生成文档时用注册过的字体族；QuestPDF 默认会内嵌子集
container.Text(text => text.Span(name).FontFamily(family));
```

**怎么验证真的内嵌了**（不要靠肉眼）：

```powershell
# 用 pdffonts（poppler-utils）看嵌入状态
pdffonts 学籍卡.pdf
#   期望：name 列里有那个备用字体，emb 列是 "yes"
#   emb = no 就说明没内嵌 —— 换台电脑就会变样

# 没有 pdffonts 时的替代：在 PDF 里搜字体描述符
Select-String -Path 学籍卡.pdf -Pattern 'FontFile' -Encoding Byte -List
```

集成测试里的做法是**渲染出真 PDF 并检查字节**（`StudentPdfRendererTests`）：
`%PDF-` 开头 + 体积合理 + 含 `FontFile`。

## 25.5 字体文件为什么不进仓库

`deploy/fonts/rare/` 是约定目录，但**仓库里不放字体文件**。原因有两个硬约束：

1. **体积**：覆盖 CJK 扩展区的字体（如 Plangothic）分片后仍有几十 MB；
2. **授权**：各字体的许可协议不同（Noto 系列是 SIL OFL，但扩展区字体未必），
   仓库分发等于替使用者做了授权决定。

所以部署时把它放进配置指向的目录：

```jsonc
// appsettings.json
"Xjgl": { "Print": {
  "DefaultFontFamily": "Microsoft YaHei",
  "UseSystemFonts": true,
  "RareCharacterFontDirectory": "/app/fonts/rare"   // 生产上挂只读卷
}}
```

**当前状态（诚实说明）**：仓库完成的是"**字体内嵌 + 缺字形报错**"这条链路，
字体文件本身需要现场按上面的方式提供。演示/开发机上若没放，
含生僻字的学籍卡会**明确报错**（而不是出方块）—— 这是设计好的行为。

## 25.6 检索：生僻字还要能搜到

一个容易被忽略的点：**按姓名搜索**。如果检索是"前端把关键字转成某种编码再发"，
生僻字就会搜不到。本项目的做法是：

- 关键字**原样**作为参数传后端（Npgsql 参数化，UTF-8 全程）；
- 后端用 `LIKE '%关键字%'`（`Contains`）匹配；
- **不要**在应用层做 `ToLower()` 之类的规范化 —— 对 CJK 无意义，还可能破坏代理对。

```csharp
// StudentAppService.BuildPredicateAsync 里的关键字条件
(!hasKeyword || s.Name.Contains(keyword!) || s.StudentNo.Contains(keyword!))
```

> 验证方法：建一个姓名含 `𠮷` 的学生，然后用**只含该字的子串**去搜（列表页关键字框），
> 必须能搜出来。搜不到就是编码链路上有一环出问题了 —— 而 `octet_length` 那步会先暴露它。

## 25.7 本章要点

1. 字体决定收在 `PrintFontRegistry` 一处，与渲染库解耦（渲染库可替换）。
2. **缺字形必须报错**，既不能画方块，更不能静默丢字 —— 后者等于改人名。
3. PDF 字体**必须内嵌**；用 `pdffonts ... emb=yes` 或搜 `FontFile` 验证，别靠肉眼。
4. 字体文件不进仓库（体积 + 授权），部署时挂目录。
5. "生僻字图片兜底"是**被否决的方案**，不要照着实现。
6. 检索链路要原样传参，不要在应用层做无意义的规范化。
