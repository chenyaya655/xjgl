# 17 用户预置与激活

> **对应阶段**：P1 ｜ **预计耗时**：2 小时 ｜ **产出**：管理员预置名单、教师自助激活的完整闭环

---

## 17.1 要解决的问题

全省要建几万个教师账号。最直觉的做法是"管理员建号 + 设初始密码"，
但这有三个绕不过去的问题：

| 问题 | 后果 |
|---|---|
| 管理员知道所有人的初始密码 | 初始口令集中在一个人手里，责任无法划分；出了事说不清 |
| 密码怎么送到教师手里？ | 短信要钱、微信要建群、打印出来发纸条不安全 |
| 教师不会主动改初始密码 | 初始口令长期有效，等于没有密码策略 |

**正确做法：管理员只预置"身份信息"，密码由教师本人第一次登录时设置。**

```
管理员：预置（姓名 + 手机号 + 所属学校 + 角色）→ 系统生成激活码 → 通知教师
教师　：打开激活页 → 填手机号 + 姓名 + 激活码 → 自己设密码 → 激活完成
```

管理员全程不接触任何人的密码，也不需要"分发密码"这个环节。

## 17.2 数据模型

```csharp
public class SysUserPredefine : FullAuditedAggregateRoot<Guid>, IXjglBusinessEntity
{
    public string RealName { get; set; } = default!;      // 真实姓名
    public string PhoneNumber { get; set; } = default!;   // 手机号，也是将来的登录名
    public string? IdCardNumber { get; set; }             // 可选，填了就多核对一项
    public Guid OrgId { get; set; }                       // 所属学校/教育局
    public string? OrgPathCode { get; set; }              // 冗余，便于按组织范围查
    public string? RoleNames { get; set; }                // 逗号分隔的角色名
    public string? Position { get; set; }                 // 岗位（如"学籍管理员"）

    public string Status { get; set; } = UserPredefineStatuses.Pending;
    public string ActivationCode { get; set; } = default!;
    public DateTime ActivationExpiresAt { get; set; }

    public Guid? ActivatedUserId { get; set; }            // 激活后指向 AbpUsers
    public DateTime? ActivatedAt { get; set; }
    public string? BatchNo { get; set; }                  // 批量预置的批次号
}

public static class UserPredefineStatuses
{
    public const string Pending = "Pending";       // 待激活
    public const string Activated = "Activated";   // 已激活
    public const string Expired = "Expired";       // 已过期
    public const string Revoked = "Revoked";       // 已吊销
}
```

**为什么激活后还要保留预置记录**：它是"这个账号是谁批的、什么时候激活的"的审计痕迹。
所以**已激活的预置记录不允许删除**（实测返回 `Xjgl:00003`，
`data.reason` 为"已激活的预置记录不允许删除，以保留审计痕迹"）。

## 17.3 激活：为什么必须是匿名接口

教师还没有账号，**登录不了**，所以激活接口必须是匿名的：

```csharp
[AllowAnonymous]
public async Task<ActivateUserResultDto> ActivateAsync(ActivateUserDto input)
{
    var predefine = await _predefines.FindAsync(p => p.PhoneNumber == input.PhoneNumber)
        ?? throw new BusinessException(XjglDomainErrorCodes.PredefinedUserNotFound)
            .WithData("reason", "预置用户不存在");

    // 1) 状态检查
    if (predefine.Status == UserPredefineStatuses.Activated)
        throw new BusinessException(XjglDomainErrorCodes.UserAlreadyActivated);

    if (predefine.ActivationExpiresAt < _clock.Now)
        throw new BusinessException(XjglDomainErrorCodes.ActivationCodeExpired);

    // 2) 激活码核对
    if (!string.Equals(predefine.ActivationCode, input.ActivationCode, StringComparison.OrdinalIgnoreCase))
        throw new BusinessException(XjglDomainErrorCodes.PredefinedUserNotFound);

    // 3) 身份核对（姓名必须一致；预置时填了身份证号则再核一项）
    if (predefine.RealName != input.RealName)
        throw new BusinessException(XjglDomainErrorCodes.IdentityMismatch)
            .WithData("reason", "姓名与预置名单不一致");

    if (!predefine.IdCardNumber.IsNullOrWhiteSpace()
        && predefine.IdCardNumber != input.IdCardNumber)
        throw new BusinessException(XjglDomainErrorCodes.IdentityMismatch)
            .WithData("reason", "身份证号与预置名单不一致");

    // 4) 建账号：用户名用手机号
    var user = new IdentityUser(_guidGenerator.Create(), input.PhoneNumber, ...);
    (await _userManager.CreateAsync(user, input.Password)).CheckErrors();
    (await _userManager.SetRolesAsync(user, ParseRoles(predefine.RoleNames))).CheckErrors();

    // 5) 回写预置记录
    predefine.Status = UserPredefineStatuses.Activated;
    predefine.ActivatedUserId = user.Id;
    predefine.ActivatedAt = _clock.Now;
    await _predefines.UpdateAsync(predefine, autoSave: true);

    return new ActivateUserResultDto { UserName = user.UserName!, ... };
}
```

### 四个安全细节

| 细节 | 为什么 |
|---|---|
| **激活码错误时返回"预置用户不存在"** | 不透露"这个手机号存在、只是码错了"，避免被用来探测哪些手机号已建档 |
| **姓名必须一致** | 防止有人拿别人的激活码激活（激活码可能被转发） |
| **身份证号可选** | 农村学校未必收集身份证号；填了才核 |
| **用户名就是手机号** | 教师最容易记住的标识；实测激活后账号名即手机号 |

## 17.4 管理端：预置、续期、吊销、批量

`UserProvisionAppService` 的关键接口：

| 方法 | 路由 | 权限 |
|---|---|---|
| 列表查询 | `GET /api/app/user-provision` | `Sys.UserProvision.Query` |
| 单条预置 | `POST /api/app/user-provision` | `Sys.UserProvision.Create` |
| 批量预置 | `POST /api/app/user-provision/import` | `Sys.UserProvision.Import` |
| 续期 | `POST /api/app/user-provision/{id}/renew-activation?validDays=30` | `Sys.UserProvision.Update` |
| 吊销 | `POST /api/app/user-provision/{id}/revoke` | `Sys.UserProvision.Update` |
| 删除 | `DELETE /api/app/user-provision/{id}` | `Sys.UserProvision.Delete` |

**批量预置的容错设计**（一次几百人，不能因为一行错就整体失败）：

```csharp
for (var i = 0; i < input.Users.Count; i++)
{
    try
    {
        var entity = await BuildPredefineAsync(input.Users[i], batchNo, i + 1);
        await _predefines.InsertAsync(entity, autoSave: true);
        result.Succeeded++;
    }
    catch (Exception ex)
    {
        // 逐行容错：单行失败不影响其它行，最后统一返回失败明细
        result.Errors.Add(new ImportPredefineErrorDto
        {
            RowIndex = i + 1,
            RealName = row.RealName,
            PhoneNumber = row.PhoneNumber,
            Message = ex is BusinessException be ? be.Message : ex.Message
        });
    }
}
```

**为什么返回"哪一行错了、错在哪"，而不是简单地整体回滚**：
管理员手里是一张 Excel，他需要的是"第 37 行手机号格式不对"这种可操作的信息，
而不是"导入失败"。

## 17.5 前端：两个页面

### 管理端 `web/apps/pc/src/views/system/user-provision/index.vue`

- 列表带状态筛选（待激活/已激活/已过期/已吊销）、**激活码一键复制**、续期、吊销；
- 组织选择用**懒加载的 `el-tree-select`** —— 全省上万所学校，
  一次拉整棵树要 1MB+，而这里只需要选一个节点；
- **批量预置做成"从 Excel 复制粘贴"**：管理员手里的名单本来就是 Excel，
  选中一片区域 `Ctrl+C` 再粘进文本框，比"导出 CSV → 上传 → 等解析"少三步，
  也不用引入 Excel 解析库。支持逗号与制表符两种分隔：

```typescript
const cells = line.split(/[,\t]/).map((c) => c.trim())
// 姓名,手机号[,身份证号][,岗位]
```

### 公开激活页 `web/apps/pc/src/views/activate/index.vue`

路由是 `meta.anonymous = true`（不需要登录）：

```typescript
{
  // 账号激活是**公开页面**：教师此时还没有账号，登录不了
  path: '/activate',
  name: 'activate',
  component: () => import('@/views/activate/index.vue'),
  meta: { title: '账号激活', anonymous: true }
}
```

并且这个页面调用接口时**用裸 axios 而不是带拦截器的实例**：

> http 实例会给请求附加本地可能已过期的令牌，并在 401 时触发"刷新令牌 + 重放"。
> 而激活本来就不该带令牌 —— 带着过期令牌去调匿名接口，
> 会被拦截器绕进刷新流程，报出与"激活失败"毫无关系的错误。

## 17.6 验证方法（整条链路）

我在真实环境跑过完整一遍，这是最有说服力的验证：

```powershell
# 1) 管理员预置
POST /api/app/user-provision  { realName, phoneNumber, orgId, roleNames:"admin", activationValidDays:30 }
# → 200，返回 activationCode 与 activationExpiresAt

# 2) 用错误姓名激活
POST /api/app/user-provision/activate { phoneNumber, realName:"张冠李戴", activationCode, password }
# → 403  Xjgl:00203「身份信息不匹配，请核对姓名与证件号」
#   data.reason = "姓名与预置名单不一致"

# 3) 用错误激活码
POST /api/app/user-provision/activate { ..., activationCode:"000000" }
# → 403「预置用户不存在」（不透露激活码是否存在）

# 4) 正确激活
POST /api/app/user-provision/activate { ...正确信息... }
# → 200，userName = 手机号，roles 正确

# 5) ★ 用新账号登录（整条链路的最终证明）
POST /connect/token  { grant_type:password, username:<手机号>, password:<刚设的密码> }
# → 200，拿到 access_token

# 6) 重复激活
# → 403  Xjgl:00201「该账号已激活，不能重复激活」

# 7) 删除已激活的预置记录
# → 403  Xjgl:00003，data.reason = "已激活的预置记录不允许删除，以保留审计痕迹"
```

**第 5 步是必须做的**：前面的接口都返回 200 也可能是因为"看起来对了"，
只有真的能登录，才证明"预置 → 激活 → 账号可用"这条链是通的。

## 17.7 踩坑记录

### 坑 1：ABP 要求邮箱必填，但很多教师没有邮箱

创建账号时服务端直接报：

```json
{"error":{"message":"您的请求无效！",
  "validationErrors":[{"message":"字段Email不可为空.","members":["email"]}]}}
```

ABP 的身份模型要求 `Email` 必填（DTO 上有 `[Required]`）。
但农村学校确实有大量教师没有邮箱 —— 为此卡住建档不合理。

**处理**：前端在邮箱留空时自动生成占位邮箱 `${userName}@xjgl.local`，
并在界面上写明原因与影响（本系统的账号激活走"预置 + 激活码"，不依赖邮件送达）。
**这是"适配现实"而不是"绕过校验"** —— 校验的意义是保证数据完整，
而占位邮箱同样是完整、唯一、格式合法的。

### 坑 2：清理顺序错了会留下脏数据

我先删了账号、才去删预置记录，而"已激活记录不允许删除"是硬规则，
于是留下一条 `ActivatedUserId` 指向已删除用户的记录。

**正确顺序**：先处理预置记录（吊销/删除），再处理账号。
**这也说明了审计保护的价值**：正是因为它不让删，才逼出了正确的操作顺序。

### 坑 3：验证脚本没打印错误体，导致查错方向

第一次创建预置用户返回 403，我没打印响应体就按"权限不足"去查权限定义与 grants ——
全都正常。后来才意识到：**本项目业务异常按 ABP 默认映射也是 HTTP 403，与鉴权失败同码**，
而当时脚本只看了状态码。

**教训**：验证脚本必须打印错误体（`code` + `message` + `data.reason`）。
本项目的错误码已经全部本地化（39 条），错误体是可读的 —— 不看纯属浪费。

### 坑 4：激活码明文存在数据库里

当前 `ActivationCode` 是明文存储的。这意味着**能读数据库的人可以激活任何未激活的账号**。

**风险等级**：中。它只影响"尚未激活"的账号，且激活还需要姓名（可选再要身份证号）匹配。
**改进方向**：存哈希，只在管理员界面上显示一次（像一次性口令那样）。
已记在方案文档的待改进项里 —— **知道问题在哪、也知道怎么修，比假装没有更重要。**

| 项 | 值 |
|---|---|

| 验证 | 预置 → 错姓名被拒 → 错码被拒 → 激活成功 → **用新账号登录成功** → 重复激活被拒 |
| 待改进 | 激活码明文存储（应存哈希，只显示一次） |
