# 11 元数据驱动的权限（一）：表怎么设计

> **对应阶段**：P1 ｜ **预计耗时**：1.5 小时 ｜ **产出**：三级元数据表，加一个模块不用改代码

---

## 11.1 要解决的问题

先看"传统写法"会怎样。绝大多数系统的权限是**编译期常量**：

```csharp
public static class Permissions
{
    public const string Students_View   = "Permissions.Students.View";
    public const string Students_Create = "Permissions.Students.Create";
    // ... 还有 200 个
}
```

然后权限分配页面的勾选框也是**写死在前端**的。

**问题在哪**：学籍系统的模块会随政策变化而增减。
比如省厅今年要求新增"随迁子女统计"模块 —— 按传统写法你必须：

1. 后端加常量、加 `[Authorize]`；
2. 前端加勾选框；
3. **重新发版部署**。

而"模块管理"如果本身是一个功能（管理员能自己加模块），那权限就必须是**数据**，不是代码。

**本项目的做法：把权限做成三级元数据。**

```
sys_subsystem（子系统）        例：Sys=系统管理、Stu=学生管理、Chg=异动管理、Pho=照片管理
   └── sys_module（模块/菜单）  例：Stu.Student=学生管理，对应一个前端页面
          └── sys_module_action（操作）  例：Stu.Student.Create=添加
```

**权限码命名规则**：`{子系统编码}.{模块编码}.{操作编码}`，例如：

| 权限码 | 含义 |
|---|---|
| `Stu.Student` | 能进入"学生管理"页面（模块级） |
| `Stu.Student.Query` | 能查看学生列表 |
| `Stu.Student.Create` | 能新增学生 |
| `Chg.Audit.Approve` | 能审核异动 |
| `Pho.Photo.Compensate` | 能触发照片存储补偿 |

---

## 11.2 为什么是三级，而不是一张表

| 方案 | 评价 |
|---|---|
| 一张 `sys_permission` 表（扁平） | 权限分配界面上没法分组展示；子系统级的"整体停用"要循环改 N 行 |
| **三级（采用）** | 天然对应"左侧一级菜单（子系统）→ 二级菜单（模块）→ 页面内按钮（操作）"的界面结构；停用子系统/模块是一条 SQL |

**三级还有一个隐性好处**：模块级权限与操作级权限**分开授**。
例如"校长只能看不能改" —— 给模块权限 + `Query`，不给 `Create/Update`。

## 11.3 动手步骤

### 步骤 1：三个实体

```csharp
// src/Xjgl.Domain/Metadata/SysSubsystem.cs
public class SysSubsystem : FullAuditedAggregateRoot<Guid>, IXjglBusinessEntity
{
    /// <summary>子系统编码，权限码的第一段。例如 Sys / Stu / Chg / Pho。</summary>
    public string Code { get; set; } = default!;

    public string Name { get; set; } = default!;

    /// <summary>前端图标名（Element Plus 图标组件名，如 Setting / School）。</summary>
    public string? Icon { get; set; }

    public int Sort { get; set; }

    public bool IsEnabled { get; set; } = true;

    public string? Remark { get; set; }
}
```

```csharp
// src/Xjgl.Domain/Metadata/SysModule.cs
public class SysModule : FullAuditedAggregateRoot<Guid>, IXjglBusinessEntity
{
    public Guid SubsystemId { get; set; }

    /// <summary>模块编码，权限码的第二段。例如 Student / Apply / Audit。</summary>
    public string Code { get; set; } = default!;

    public string Name { get; set; } = default!;

    public string PermissionName { get; set; } = default!;   // 冗余存 "Stu.Student"

    /// <summary>前端路由路径，如 /student/list。</summary>
    public string? Path { get; set; }

    /// <summary>前端组件路径，如 student/list/index。</summary>
    public string? Component { get; set; }

    public string? Icon { get; set; }

    public int Sort { get; set; }

    public bool IsEnabled { get; set; } = true;

    /// <summary>隐藏但可用（例如只通过按钮跳转进入的详情页）。</summary>
    public bool IsHidden { get; set; }

    /// <summary>外链菜单（跳到别的教育系统）。</summary>
    public bool IsExternal { get; set; }

    /// <summary>允许访问的组织层级，逗号分隔，如 "Province,City"；为空表示不限。</summary>
    public string? OrgTypes { get; set; }

    public string? Remark { get; set; }
}
```

```csharp
// src/Xjgl.Domain/Metadata/SysModuleAction.cs
public class SysModuleAction : FullAuditedAggregateRoot<Guid>, IXjglBusinessEntity
{
    public Guid ModuleId { get; set; }

    /// <summary>操作编码，权限码的第三段。例如 Query / Create / Update / Delete / Import / Export / Print。</summary>
    public string Code { get; set; } = default!;

    public string Name { get; set; } = default!;             // 界面上显示的按钮名，如"添加"

    /// <summary>操作类型，与 Code 同名，便于前端按类型渲染按钮样式。</summary>
    public string ActionType { get; set; } = default!;

    public string PermissionName { get; set; } = default!;   // 冗余存 "Stu.Student.Create"

    public int Sort { get; set; }

    public bool IsEnabled { get; set; } = true;

    /// <summary>新建角色时是否默认勾选。</summary>
    public bool IsDefaultGranted { get; set; }
}
```

> **注意 `PermissionName` 是冗余存储的**（不是每次拼出来的）。
> 为什么？因为权限校验是**每次请求都发生**的高频操作，
> 而读取快照时需要立刻拿到权限名。冗余一个字符串，换来的是"不用 join 三张表"。

### 步骤 3：幂等的写入逻辑

```csharp
private async Task EnsureActionsAsync(SysModule module, string subsystemCode, ModuleSeed moduleSeed)
{
    var existing = await _actions.GetListAsync(a => a.ModuleId == module.Id);
    var existingCodes = existing.Select(a => a.Code).ToHashSet(StringComparer.Ordinal);

    var order = 0;
    foreach (var actionSeed in moduleSeed.Actions)
    {
        order += 10;

        if (existingCodes.Contains(actionSeed.Code))
        {
            continue;      // ★ 幂等：已存在就跳过，不重复插
        }

        var action = new SysModuleAction(
            _guidGenerator.Create(),
            module.Id,
            actionSeed.Code,
            actionSeed.Name,
            actionSeed.ActionType,
            $"{subsystemCode}.{moduleSeed.Code}.{actionSeed.Code}",   // 拼权限名
            order);

        await _actions.InsertAsync(action, autoSave: true);
    }
}
```

**为什么种子要幂等**：DbMigrator 每次发版都会跑一遍。
不幂等的话，第二次发版就会出现两套"学生管理"模块，
管理员在权限页面上看到重复项，勾了一个发现没用（因为另一个才是真的）。

## 11.4 验证方法

**① 表里数据正确**

```powershell
docker exec -it xjgl-postgres psql -U xjgl -d xjgl -c `
  "SELECT s.code AS 子系统, m.code AS 模块, m.permission_name, m.path
   FROM sys_module m JOIN sys_subsystem s ON s.id = m.subsystem_id
   ORDER BY s.sort, m.sort;"
```

期望看到 4 个子系统、11 个模块，`path` 是 `/student/list` 这类前端路由。

**② 权限码拼装正确**

```powershell
docker exec -it xjgl-postgres psql -U xjgl -d xjgl -c `
  "SELECT permission_name, name FROM sys_module_action ORDER BY permission_name LIMIT 12;"
```

期望形如 `Stu.Student.Query | 查看`。

**③ 幂等**

```powershell
dotnet run --project src\Xjgl.DbMigrator 2>&1 | Select-String "当前共有"
dotnet run --project src\Xjgl.DbMigrator 2>&1 | Select-String "当前共有"
# 两次输出必须逐字一致
```

**④ 唯一索引真的存在**（防止并发/重复插入）

```powershell
docker exec -it xjgl-postgres psql -U xjgl -d xjgl -c "\d sys_module_action"
```

> 本项目当前**没有**在 `sys_module(code)` / `sys_module_action(module_id, code)` 上建唯一索引，
> 幂等性靠应用层的 `existingCodes` 判断。**这是一个应该在 P1 收尾时补上的约束** ——
> 数据库层的唯一约束才是最后一道防线（尤其是并发执行 DbMigrator 时）。

## 11.5 踩坑记录

### 坑 1：权限码重复（模块级与操作级同名）

模块权限叫 `Stu.Student`，如果某个操作也叫 `Student`，
拼出来就是 `Stu.Student.Student` —— 不冲突但很怪。
真正危险的是**两个模块用了同一个 code**（例如两个子系统都有 `User` 模块）。
所以权限码必须带**子系统**那一段，不能只用 `模块.操作`。

### 坑 2：改了模块编码，历史授权全部失效

权限名里含编码。如果管理员把 `Stu` 改成 `Student`，
数据库里 `AbpPermissionGrants` 里存的还是旧权限名 —— **所有授权瞬间失效**。

**约定**：**模块编码一经使用不要改**（界面上应该把它设为只读，或改的时候给出警告）。
本项目的 `CreateUpdateModuleDto` 允许改 Code，这是一个**待改进点**。

### 坑 3：`IsHidden` 与 `IsEnabled` 混淆

- `IsEnabled = false`：模块停用，**菜单不显示、接口也拒绝**（权限校验走不到）；
- `IsHidden = true`：菜单不显示，但**权限仍然有效**。

典型场景：学生详情页 `/student/detail` 是隐藏菜单 —— 它不该出现在左侧菜单里，
但从列表点进去必须能打开。

### 坑 4：忘了给新模块的权限码加到前端常量里

前端 `MetadataPermissions` 是后端常量的**镜像**（第 47 章）。
后端加了新权限、前端没加，症状是"那个按钮永远不显示"，
而且**不报错**（因为 `can('Xxx.Yyy')` 只是返回 false）。

**约定**：改后端 `MetadataPermissions.cs` 时，顺手搜一下前端同名文件。
