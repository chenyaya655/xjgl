# 03 手动搭出 ABP 解决方案骨架

> **对应阶段**：P0 ｜ **预计耗时**：1.5 小时 ｜ **产出**：能编译、能启动、能打印出 ABP 模块列表的空解决方案

---

## 3.1 要解决的问题

ABP 官方脚手架 `abp new` 能一键生成模板，但本项目选择**手写**，原因有三条（都很实际）：

| 原因 | 说明 |
|---|---|
| **要加第二个 ORM** | 模板生成的是纯 EF Core 结构，没有地方放 SqlSugar 集成层。手写时可以把 `Xjgl.SqlSugarCore` 作为一等公民安排进依赖图 |
| **要理解每个文件** | 这是学习项目。`abp new` 一次生成 200 多个文件，其中一半你永远不看 —— 出了问题不知道从哪查 |
| **受限网络下不可用** | `abp new` 会去 abp.io 下载模板包并写入 `~/.abp`，内网/受限环境直接失败 |

> 如果你在正常网络环境且只想快速起步，用 `abp new Xjgl -t app -u mvc --database-provider efcore`
> 生成后再按第 04 章的分层改造，也完全可以。**本文档走手写路线。**

## 3.3 动手步骤

### 步骤 1：建目录与解决方案

```powershell
# 路径随意，本教程后面统一用 <仓库根> 指代这一层。
# 下面用 D:\Xjgl 只是举例 —— **不要照抄 D:\StudentManagement**，
# 那是笔者本机的目录名，你抄了不会报错，但后面所有命令的相对路径都会与教程对不上。
mkdir D:\Xjgl
cd D:\Xjgl
mkdir src, test, deploy, docs

dotnet new sln -n Xjgl
```

### 步骤 2：建类库项目

```powershell
# 主项目（除 Host 外都是类库）
dotnet new classlib -n Xjgl.Domain.Shared        -o src\Xjgl.Domain.Shared
dotnet new classlib -n Xjgl.Domain               -o src\Xjgl.Domain
dotnet new classlib -n Xjgl.Application.Contracts -o src\Xjgl.Application.Contracts
dotnet new classlib -n Xjgl.Application          -o src\Xjgl.Application
dotnet new classlib -n Xjgl.EntityFrameworkCore  -o src\Xjgl.EntityFrameworkCore
dotnet new classlib -n Xjgl.SqlSugarCore         -o src\Xjgl.SqlSugarCore
dotnet new classlib -n Xjgl.HttpApi              -o src\Xjgl.HttpApi

# 可执行项目
dotnet new web      -n Xjgl.HttpApi.Host         -o src\Xjgl.HttpApi.Host
dotnet new console  -n Xjgl.DbMigrator           -o src\Xjgl.DbMigrator

# 测试项目（用 xunit v3，见第 50 章）
dotnet new classlib -n Xjgl.TestBase             -o test\Xjgl.TestBase

dotnet new xunit    -n Xjgl.Application.Tests    -o test\Xjgl.Application.Tests
```

删掉模板自动生成的 `Class1.cs`：

```powershell
Get-ChildItem -Recurse -Filter Class1.cs | Remove-Item
Get-ChildItem -Recurse -Filter UnitTest1.cs | Remove-Item
```

### 步骤 3：全部加入解决方案

```powershell
dotnet sln add (Get-ChildItem -Recurse -Filter *.csproj | ForEach-Object FullName)
```

### 步骤 4：写模块类

ABP 的"模块"是它的组织单元 —— 每个项目暴露一个 `AbpModule` 子类，
ABP 靠它做依赖注入、配置、初始化。

**最底层：`Xjgl.Domain.Shared/XjglDomainSharedModule.cs`**

```csharp
using Volo.Abp.Modularity;
using Volo.Abp.Localization;
using Volo.Abp.Localization.ExceptionHandling;
using Volo.Abp.Validation.Localization;
using Volo.Abp.VirtualFileSystem;

namespace Xjgl;

[DependsOn(
    typeof(AbpValidationModule)   // 提供数据注解与本地化校验消息
)]
public class XjglDomainSharedModule : AbpModule
{
    public override void ConfigureServices(ServiceConfigurationContext context)
    {
        // 本地化资源：错误码、校验消息都从这里取
        Configure<AbpLocalizationOptions>(options =>
        {
            options.Resources
                .Add<XjglResource>("zh-Hans")   // 默认中文，符合政务系统实际
                .AddVirtualJson("/Localization/Xjgl");
        });

        // 让数据注解的报错也走本地化资源
        Configure<AbpExceptionLocalizationOptions>(options =>
        {
            options.MapCodeNamespace("Xjgl", typeof(XjglResource));
        });
    }
}
```

配套两个文件：

```csharp
// XjglResource.cs
using Volo.Abp.Localization;

namespace Xjgl;

[LocalizationResourceName("Xjgl")]
public class XjglResource
{
}
```

```json
// Localization/Xjgl/zh-Hans.json（需在 csproj 里作为嵌入资源）
{
  "culture": "zh-Hans",
  "texts": {
    "AppName": "河南省学籍管理系统"
  }
}
```

`.csproj` 里要声明嵌入资源与虚拟文件系统：

```xml
<ItemGroup>
  <EmbeddedResource Include="Localization\**\*.json" />
  <Content Remove="Localization\**\*.json" />
</ItemGroup>
```

**领域层：`Xjgl.Domain/XjglDomainModule.cs`**

```csharp
using Volo.Abp.Domain;
using Volo.Abp.Modularity;
using Volo.Abp.Identity;
using Volo.Abp.PermissionManagement.Identity;
using Volo.Abp.SettingManagement;
using Volo.Abp.AuditLogging;

namespace Xjgl;

[DependsOn(
    typeof(XjglDomainSharedModule),
    typeof(AbpDddDomainModule),                    // ABP 领域层基础（聚合根、仓储、领域服务）
    typeof(AbpIdentityDomainModule),               // 用户与角色
    typeof(AbpPermissionManagementDomainIdentityModule),
    typeof(AbpSettingManagementDomainModule),      // 系统设置
    typeof(AbpAuditLoggingDomainModule)            // 审计日志
)]
public class XjglDomainModule : AbpModule
{
}
```

**其余模块按依赖方向逐个写**（见 3.4 的依赖图），
每个都只有 `[DependsOn(...)]` 加少量配置。

### 步骤 5：跑起来

`Xjgl.HttpApi.Host/Program.cs`：

```csharp
using Microsoft.AspNetCore.Builder;
using Microsoft.Extensions.Hosting;
using Serilog;
using Serilog.Events;

namespace Xjgl;

public class Program
{
    public static async Task<int> Main(string[] args)
    {
        Log.Logger = new LoggerConfiguration()
            .MinimumLevel.Information()
            .MinimumLevel.Override("Microsoft", LogEventLevel.Warning)
            .Enrich.FromLogContext()
            .WriteTo.Async(c => c.Console())
            .WriteTo.Async(c => c.File("Logs/logs.txt"))
            .CreateLogger();

        try
        {
            Log.Information("正在启动 Xjgl.HttpApi.Host ...");

            var builder = WebApplication.CreateBuilder(args);
            builder.Host
                .AddAppSettingsSecretsJson()
                .UseAutofac()          // ABP 支持 Autofac 或 MS DI，本项目用 Autofac
                .UseSerilog();

            await builder.AddApplicationAsync<XjglHttpApiHostModule>();

            var app = builder.Build();
            await app.InitializeApplicationAsync();   // ← 模块初始化在这里发生
            await app.RunAsync();

            return 0;
        }
        catch (Exception ex)
        {
            Log.Fatal(ex, "宿主异常终止！");
            return 1;
        }
        finally
        {
            await Log.CloseAndFlushAsync();
        }
    }
}
```

```powershell
dotnet run --project src\Xjgl.HttpApi.Host
```

## 3.4 依赖方向（必须记住，否则一定写出死循环）

```
                Domain.Shared
                     ↑
      ┌──────────────┴──────────────┐
      │                             │
   Domain                    Application.Contracts
      ↑                             ↑
      │                             │
      ├── EntityFrameworkCore ──────┤
      ├── SqlSugarCore ─────────────┤
      │                             │
      └────────► Application ◄──────┘
                     ↑
                  HttpApi
                     ↑
              HttpApi.Host（组合根）

  DbMigrator → EntityFrameworkCore + SqlSugarCore
  test/*     → Application + SqlSugarCore + TestBase
```

**三条铁律：**

1. **`Domain` 不引用任何 ORM**（既不引用 EF Core 也不引用 SqlSugar）。
   为什么？因为领域规则要能被纯单元测试覆盖 —— 本项目 129 个单元测试
   全都不需要数据库，靠的就是这一条。
2. **`Application` 只依赖 `Domain` 与 `Application.Contracts`**，不依赖 `HttpApi`。
3. **只有 `HttpApi.Host` 认识所有实现**（它是组合根，负责把接口和实现接起来）。

## 3.5 验证方法

**① 编译通过**

```powershell
dotnet build Xjgl.sln
# 期望：生成成功，0 个错误
```

**② 启动时能看到 ABP 模块被加载**

```powershell
dotnet run --project src\Xjgl.HttpApi.Host
```

把日志级别调到 Debug 后会打印模块列表：

```
[DBG] Loaded ABP modules:
[DBG] - Xjgl.XjglHttpApiHostModule
[DBG]   - Volo.Abp.Autofac.AbpAutofacModule
[DBG]   - Volo.Abp.AspNetCore.AbpAspNetCoreModule
...
[DBG]   - Xjgl.XjglHttpApiModule
[DBG]     - Xjgl.XjglApplicationContractsModule
[DBG]       - Xjgl.XjglDomainSharedModule
```

**看到这棵树是"骨架搭对了"的最直接证据**：
- 每个模块只出现一次（说明没有重复注册）；
- 缩进体现依赖顺序 —— 被依赖的排在更里层。

**③ 依赖方向没有被破坏**

```powershell
dotnet list src\Xjgl.Domain\Xjgl.Domain.csproj reference
```

期望**只看到 `Xjgl.Domain.Shared`**。
如果哪天这里冒出了 `Xjgl.SqlSugarCore` 或 `Xjgl.EntityFrameworkCore`，
说明铁律 1 被破坏了 —— 这时先停下来修，不要继续往下写。

## 3.6 踩坑记录

### 坑 1：模块类忘记 `[DependsOn]`，配置不生效

`Configure<AbpAuditingOptions>` 写在 `XjglDomainModule` 里，
但 `XjglDomainModule` 没有依赖 `AbpAuditLoggingDomainModule`，
结果是审计日志模块根本没被加载，配置对象被创建了却没人用 —— **不报错，只是不生效**。

排查方法：看启动日志的模块树，确认你依赖的模块在树里。

### 坑 2：`await app.InitializeApplicationAsync()` 漏写

漏了这行，ABP 的模块初始化不会执行：数据库种子不跑、动态权限不注册、
后台任务不启动。表现是"接口能通、但拿不到任何权限、报 403"。

### 坑 3：本地化 JSON 没打进程序集

`Localization/Xjgl/zh-Hans.json` 必须在 `.csproj` 里声明为 `EmbeddedResource`，
否则 ABP 的虚拟文件系统读不到，报 `Could not find the localization resource`。

开发期可以额外配置"物理目录替换嵌入资源"，改 JSON 立即生效
（见 `XjglHttpApiHostModule.ConfigureVirtualFileSystem`）——
**但要注意：这个映射依赖 ContentRoot 是源码目录**。
直接用 `bin` 目录里的 exe 启动时 ContentRoot 会变，
如果代码里不做 `Directory.Exists` 判断，`DirectoryNotFoundException`
会把整个应用带崩（我在这个项目上真实踩过，见第 04 章的修复说明）。

### 坑 4：项目名与命名空间

`dotnet new classlib -n Xjgl.Domain.Shared` 会把根命名空间设为 `Xjgl.Domain.Shared`。
但本项目希望**所有项目的根命名空间统一是 `Xjgl`**（这样 `Xjgl.Students.StudentAppService`
不用管它在哪个程序集）。做法是在每个 `.csproj` 里加：

```xml
<PropertyGroup>
  <RootNamespace>Xjgl</RootNamespace>
</PropertyGroup>
```

否则你会写出 `Xjgl.Domain.Shared.Xjgl.Students...` 这种荒唐的命名空间。
