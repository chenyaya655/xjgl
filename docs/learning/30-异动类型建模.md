# 30 异动类型建模：编码 / 终止级别 / 时间窗 / 年级控制

> 对应代码：`src/Xjgl.Domain/Changes/ChangeTypeAndFlow.cs`、
> `src/Xjgl.Application/Changes/ChangeTypeAppService.cs`
> 对应测试：`test/Xjgl.Application.Tests/Changes/ChangeTypeAppServiceTests.cs`

## 30.1 要解决的问题

"异动类型"表面上是张字典表（转学/休学/复学…），实际上它是**业务规则的主要载体**。
本系统把下面这些规则都挂在类型上，而不是写死在代码里：

| 规则 | 字段 | 不配会怎样 |
|---|---|---|
| 审到哪一级 | `MaxApproveLevel` | 省级节点永远不截断，休学也要省长批 |
| 什么时候能申请 | `ApplyWindowStart/End` | 全年任何时间都能转学（政策上通常限定学期初） |
| 哪些年级允许 | `GradeScope` | 六年级也能休学转出，数据上出现不合规记录 |
| 学籍状态怎么变 | `Before/AfterStatusCode` | 审批通过后学生状态不会变 |
| 要不要换学校 | `AllowCrossSchool` | 申请单上让用户选目标学校（休学不该选） |
| 要不要换年级/班级 | `AffectGrade` / `AffectClass` | 审批后年级班级被错误清空或保留 |
| 能不能跨学年 | `AllowCrossAcademicYear` | 跨学年的转学被静默允许 |
| 一年能申请几次 | `MaxApplyTimesPerYear` | 同一学生被反复转出转入 |
| 必须传附件吗 | `RequireAttachment` | 转学证明材料缺失也能提交 |
| 需要对方学校确认吗 | `NeedPeerSchoolConfirm` | 转出校单方面就能把学生转走 |

一条一条看，会发现**它们全都是"校验条件"或"生效动作"**，
而不是流程结构 —— 这正是把它们放在类型上、而不是做成流程分支的原因（见第 29 章）。

## 30.2 第一步：编码（`Code`）与类别（`CategoryCode`）

```csharp
public class StuChangeType : FullAuditedAggregateRoot<Guid>, IXjglBusinessEntity
{
    public string Code { get; set; } = default!;          // 内部编码，如 TRANSFER
    public string Name { get; set; } = default!;          // 显示名，如 转学
    public string? CategoryCode { get; set; }             // 码值：CHANGE_TYPE 类别下的码
    // ...
}
```

两个编码的**用途不同**，不要混：

- `Code`：程序内唯一标识，**不可变**（申请单会引用它做统计口径）；
- `CategoryCode`：对应微代码表 `CHANGE_TYPE` 里的码值（如 `01` 转学、`02` 休学），
  用于**与外部系统交换**（省厅报表按码值汇总）。

> **为什么必须校验 `Before/AfterStatusCode` 是码表里真实存在的值**：
> 这两个字段会在**审批通过时直接写进学生主档的 `student_status_code`**。
> 配错一次、审批一次，就给学生写上了一个码表里不存在的状态 ——
> 而且此后"学籍状态"下拉里再也选不中它，学生列表那一列显示空白。
> 所以 `ChangeTypeAppService.EnsureStudentStatusCodesAsync` 在保存时校验，
> 前端下拉也**只能从码表取值**（第 16 章 / 前端规约）。

```csharp
// 保存前校验：值必须来自码表 STUDENT_STATUS
await EnsureStudentStatusCodesAsync(input.BeforeStatusCode, input.AfterStatusCode);
```

## 30.3 第二步：终止级别（`MaxApproveLevel`）决定"审到哪"

取值是 `School / County / City / Province` 四级（`ApproveLevels`）。
它的作用在流程实例化的**第 ② 步：截断**：

```csharp
// ChangeFlowPlanner.Plan 里
if (ApproveLevels.GetOrder(level) > maxLevelOrder)
{
    result.Warnings.Add($"节点「{node.Name}」超出审核终止级别「{...}」，已截断。");
    continue;   // 丢掉，但仍记一条 warning
}
```

两个实现细节值得注意：

1. **级别由"解析出来的组织的 `OrgType`"推出**，而不是节点上写死。
   所以同一个模板，在"市直属学校"与"县属学校"下截断结果可能不同 —— 这是**对的**；
2. **截断要产出 warning**，而不是默默丢掉。否则业务人员配了 6 个节点却只跑了 3 个，
   会以为系统少跑了流程。前端把 warnings 显示在流程预览里（第 33 章）。

## 30.4 第三步：时间窗（`ApplyWindowStart/End`）——只写月日，不写年份

这是个容易做错的细节。**时间窗不能存完整日期**：

```csharp
// ❌ 存成 2026-03-01 / 2026-03-31：明年就得改数据，而且改一次漏一次
public DateTime ApplyWindowStart { get; set; }

// ✅ 存成 "03-01" / "03-31"：每年自动生效
[StringLength(5)]
public string? ApplyWindowStart { get; set; }
```

校验逻辑是"把当前年份拼上去比较"：

```csharp
// 支持跨年窗口（如 12-15 ~ 01-15），所以不能简单地 start <= now <= end
private static bool InWindow(string? start, string? end, DateTime now)
{
    if (start.IsNullOrWhiteSpace() || end.IsNullOrWhiteSpace()) return true;  // 未配置=不限

    var s = ParseMonthDay(start, now.Year);
    var e = ParseMonthDay(end, now.Year);

    return s <= e
        ? now >= s && now <= e
        : now >= s || now <= e;   // 跨年
}
```

> **实测**：测试里用 `01-01 ~ 01-02` 作为窗口来断言"当前必然不在窗口内"，
> 这比"临时把系统时间改到窗口内"稳定得多。

## 30.5 第四步：年级白名单（`GradeScope`）

格式是逗号分隔的年级码（如 `"01,02,03"`），空表示不限。
它不是外键而是**码值列表**，原因与时间窗类似：年级码（01=一年级）是国标码值，
而 `sys_grade` 里的是"某校某学年的具体年级记录" —— 类型规则该按**码值**表达，
而不是绑定到某一所学校的具体数据上。

```csharp
// 提交申请时校验
if (!type.GradeScope.IsNullOrWhiteSpace())
{
    var allowed = type.GradeScope.Split(',', StringSplitOptions.RemoveEmptyEntries);
    var studentGradeCode = await GetGradeCodeAsync(student.GradeId);

    if (!allowed.Contains(studentGradeCode))
        throw new BusinessException(XjglDomainErrorCodes.GradeNotAllowedForChange);
}
```

## 30.6 第五步：申请次数上限（`MaxApplyTimesPerYear`）

```csharp
// 同一学生 + 同一异动类型 + 同一学年内的申请单数量
var count = await _applies.GetCountAsync(a =>
    a.StudentId == student.Id &&
    a.ChangeTypeId == type.Id &&
    a.ApplyAcademicYear == academicYear);

if (type.MaxApplyTimesPerYear > 0 && count >= type.MaxApplyTimesPerYear)
    throw new BusinessException(XjglDomainErrorCodes.ChangeApplyTimesExceeded);
```

注意 `ApplyAcademicYear` 是**申请单上的快照字段**，不是从学生主档实时读的。
原因：学生转学后学年字段会变，用实时值去数历史申请会算错。

## 30.8 本章要点

1. 异动类型是**业务规则的载体**：终止级别、时间窗、年级白名单、状态变更都在它身上。
2. `Before/AfterStatusCode` 会**直接写进学生主档**，必须校验它在码表里存在；前端下拉只能取自码表。
3. 时间窗存 **`MM-dd`** 而不是完整日期，并要支持**跨年窗口**。
4. 年级白名单用**码值列表**（`01,02`），不要绑定到具体学校的年级记录。
5. 申请次数要按**申请单上的学年快照**统计，不能用学生主档的实时学年。
6. 截断必须产出 warning 并在界面上显示，否则"少跑了几步"没人知道。
