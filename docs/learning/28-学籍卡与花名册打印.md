# 28 学籍卡与花名册打印：PDF、字体与"纸质件不能出错"

> 对应代码：`src/Xjgl.Domain.Shared/Printing/PrintModels.cs`、
> `src/Xjgl.Reporting/`（QuestPDF 实现）、
> `src/Xjgl.Application/Students/StudentPrintService.cs`、
> `src/Xjgl.HttpApi/Controllers/StudentPrintController.cs`
> 对应测试：`test/Xjgl.Domain.Tests/Printing/StudentPdfRendererTests.cs`、
> `test/Xjgl.Application.Tests/Students/StudentPrintTests.cs`

## 28.1 要解决的问题

方案文档里早就写死了方向：**打印走 PDF 嵌入字体路线，不走"导出 Excel 再打印"**。理由是学籍卡与
花名册是要盖章归档的**正式纸质件**：

| 走 Excel 的问题 | 走 PDF 的好处 |
|---|---|
| 每个人机器上字体不同，中文/生僻字直接变方块 | 字体**嵌进 PDF**，在哪台机器上打开都一样 |
| 排版随列宽漂移，一页放几个人不确定 | 版面固定：学籍卡一页一人，花名册横向多页带页码 |
| 打印出来没有"第几页/共几页" | 页脚页码 + 每页重复表头，散页也能拼回去 |

## 28.2 第一步：把"渲染"独立成一个项目（依赖倒置）

```
src/Xjgl.Domain.Shared/Printing/PrintModels.cs   ← 接口 + 打印视图模型（无第三方依赖）
src/Xjgl.Reporting/                              ← QuestPDF 实现（只被 Host 装配）
src/Xjgl.Host  → DependsOn(XjglReportingModule)
```

三条理由：

1. **业务层不该认识渲染库**：`StudentPrintService` 只依赖 `IStudentCardPdfRenderer`；
   换渲染库（或换成本地服务出 PDF）只改一个项目。
2. **视图模型隔离了"排版"与"接口契约"**：`StudentCardModel` 只有打印需要的字段。
   DTO 加字段不会影响排版；渲染器也不会被迫依赖整个业务模型。
3. **原生依赖不污染业务层**：QuestPDF 带原生渲染库，放最外层项目里，业务层不必为它操心运行时环境。

连"渲染库抛的异常"也要翻译一次：

```csharp
// 渲染库的异常类型属于基础设施细节，应用层若直接 catch 它，
// 就等于让业务代码依赖具体渲染库（换库要改业务代码，分层也白做了）
public sealed class PrintRenderingException : Exception
{
    public bool MissingFont { get; }
}
```

## 28.3 第二步：字体（这一块最容易上线才炸）

QuestPDF 的默认字体（Lato）**不含中文**。不指定字体族，整张卡片就是方块。因此 `PrintFontRegistry`
在**每次渲染前**（幂等）做三件事：

```csharp
// QuestPDF 要求在使用前声明许可证等级
QuestPDF.Settings.License = QuestPDF.Infrastructure.LicenseType.Community;

// 缺字体族本身不致命（会退到其它已注册字体），
// 但**画不出字形**必须报错：纸质学籍卡上出现方块是绝对不能接受的
QuestPDF.Settings.ThrowOnMissingFontFamilies = false;
QuestPDF.Settings.ThrowOnMissingTextGlyphs = true;

// 生僻字字体目录（可选）
if (!RareCharacterFontDirectory.IsNullOrWhiteSpace() && Directory.Exists(...))
{
    QuestPDF.Settings.FontDiscoveryPaths.Add(RareCharacterFontDirectory!);
}
```

### 字体策略的取舍

| 环境 | 字体从哪来 | 配置 |
|---|---|---|
| Windows 服务器（本项目主要部署形态） | 系统字体（微软雅黑） | `UseSystemFonts=true`（默认）、`DefaultFontFamily=Microsoft YaHei` |
| Linux 容器 | 镜像里装的 Noto CJK | `apt-get install fonts-noto-cjk`、`DefaultFontFamily=Noto Sans CJK SC` |
| 生僻字 | 单独目录（Plangothic 等） | `RareCharacterFontDirectory=/app/fonts/rare` |

> QuestPDF 2026 **默认不使用系统字体**（为了容器/云环境输出稳定）。
> 这个默认值对"输出可复现"是好事，但会让 Windows 上开箱即用变成一堆方块。
> 因此本项目显式设成 `UseSystemFonts=true`，并在部署文档里写明容器该怎么改。

### 渲染失败要翻译成运维能懂的话

```csharp
catch (PrintRenderingException ex)
{
    throw new BusinessException(XjglDomainErrorCodes.ValidationFailed)
        .WithData("reason", ex.MissingFont
            ? "生成 PDF 失败：服务器缺少可用的中文字体。请在服务器上安装中文字体，" +
              "或把 Xjgl:Print:RareCharacterFontDirectory 指向随应用部署的字体目录。"
            : "生成 PDF 失败，请查看服务端日志。");
}
```

直接冒泡的话，用户看到的是 500 + 一堆英文堆栈 —— 而真正的原因是**运维问题**（服务器没装字体）。

## 28.4 第三步：版面即业务规则

排版不是美术问题，学籍卡上的每一处留白与标注都是业务决定：

| 决定 | 理由 |
|---|---|
| 身份证号**打掩码** | 纸质件会被拍照、传阅、归档，明文收不回来 |
| 缺照片时写"未采集照片"**而不是留白** | 留白看起来像"排版省略"，写清楚才能让经办人知道要去补 |
| 姓名含生僻字时标注"请核对原件" | 方块字没法核对，标注能让经办人知道该核对什么 |
| 花名册**不打印家庭住址与联系电话** | 花名册是点名/核对用途，把全校家长电话印在纸上属于过度收集 |
| 表头每页重复 + 页脚"第 X 页 / 共 Y 页" | 散页后必须能拼回去 |
| 页脚写打印时间 + 学校盖章/经办人签字栏 | 纸质件必须能追溯到"什么时候、由谁出的" |
| 花名册**沿用当前筛选条件** | 否则"筛出二班来打印"会印出全校，而错误要到校对时才发现——纸已经印出来了 |

## 28.5 第四步：为什么用手写控制器

```csharp
[Route("api/print")]
[Authorize(MetadataPermissions.Stu.Student.Print)]
public class StudentPrintController : XjglController
{
    [HttpGet("student-card/{studentId}")]
    public async Task<IActionResult> StudentCardAsync(Guid studentId, CancellationToken ct)
    {
        var file = await _printService.RenderStudentCardAsync(studentId, ct);
        return File(file.Content, file.ContentType, file.FileName);
    }
}
```

与照片的二进制接口同样的理由：**产物是二进制**。走自动 API 的话 `byte[]` 会被序列化成 base64
塞进 JSON（200KB 的 PDF 变 270KB 字符串），浏览器也拿不到"另存为"的文件名。
因此 `IStudentPrintService` **故意不实现 `IApplicationService`**，由控制器显式接管响应头。

权限用现成的 `Stu.Student.Print`（第 11 章的元数据动作表里已经有 `Print`，不用加新权限码）。

## 28.6 验证方法

### ① 单元测试（11 个）：不碰数据库，直接验渲染

| 用例 | 断言 |
|---|---|
| 合法 PDF | 前 5 字节是 `%PDF-`、末尾 `%%EOF`、体积 > 2KB |
| 内容随数据变化 | 换姓名后**整份字节不同**（`SequenceEqual`） |
| 生僻字姓名 | 不抛异常（字形检查开着还能过，说明字体确实可用） |
| 缺照片 / 无监护人 | 照样出卡 |
| 超长地址 / 200 字工作单位 | 不崩（排版容器会换行/截断，而不是溢出报错） |
| 多页花名册 | 120 行 → 体积 > 10KB（确实分页了） |

> 注意"内容随数据变化"这条断言：**不要用"长度不同"**来判。
> PDF 是压缩流，两份内容不同但长度恰好相同的概率并不低 —— 本项目就因此偶发失败过一次。

### ② 集成测试（10 个）：真实数据库 + 真实渲染

覆盖：学籍卡的产出与差异、越权被拒（卡片含出生日期/住址/监护人电话）、不存在学生 404、
花名册行数与列表一致、空表也能出、脱敏开关、范围外学校被拒、不指定学校也不越界。

### ③ 端到端验证（真实 HTTP + 检查 PDF 内部）

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "http://localhost:44300/api/print/student-card/$STUDENT_ID" -o card.pdf

# 期望：HTTP 200、66KB、%PDF- 开头、Content-Type: application/pdf
```

更关键的是**检查字体真的嵌进去了**（只看"返回了 PDF"是不够的）：

```powershell
$raw = [System.Text.Encoding]::ASCII.GetString([IO.File]::ReadAllBytes('card.pdf'))
$raw.Contains('FontFile2')      # True  → 字体已内嵌
$raw.Contains('MicrosoftYaHei') # True  → 嵌的是哪个字体
$raw.Contains('Identity-H')     # True  → CJK 需要的 CID 编码
if ($raw -match '/MediaBox\s*\[([^\]]+)\]') { $Matches[1] }   # 0 0 595 842 → A4 纵向
```

## 28.7 踩坑记录

| 现象 | 根因 | 教训 |
|---|---|---|
| 9 个渲染用例全挂：`Please configure the QuestPDF license` | 许可证声明写在 ABP 模块的 `ConfigureServices` 里 —— 只覆盖"通过 ABP 装配"的路径，**单元测试直接 new 渲染器就漏了** | 初始化代码要放在"使用前必经的那一处"（本项目最终放在渲染器调用的 `EnsureInitialized` 里） |
| 中文整片画不出：`uses font families that are not available: 'Microsoft YaHei'` | QuestPDF 2026 默认**不使用系统字体**（`System fonts: disabled`） | 先读库的默认值，再决定要不要覆盖：这类"默认更安全但对本场景不适用"的默认值还有很多 |
| 表头单元格编译不过 | QuestPDF 的表头 API 是 `Header(Action<TableCellDescriptor>)` —— 传进来的是**格子游标**，每次 `header.Cell()` 前进一格 | **没靠猜**：直接读包里的 `QuestPDF.xml` 成员签名确认（反射在 PowerShell 里因依赖加载失败，XML 文档更可靠） |
| 打印件上出现方块 | 生僻字字体文件未随仓库分发（体积大、授权各异） | 卡片上打印"请核对原件"作为兜底提示；部署文档写明字体放哪 |
| 花名册"筛了班级却印出全校"（潜在） | 如果导出/打印另起一套查询 | 花名册复用列表查询并**带上当前筛选条件**，与界面口径完全一致 |
| 一张卡都打不出来（500） | 服务器没装中文字体，而渲染直接抛异常 | 这是**故意**的：宁可报错也不出方块件；但必须把异常翻译成运维能懂的提示 |

## 28.8 部署侧的两件事（详见 53 章）

1. **镜像里装字体**：`apt-get install -y --no-install-recommends fonts-noto-cjk`；
2. **提供字体挂载点**：`- ${RARE_FONT_DIR:-./fonts/rare}:/app/fonts/rare:ro`。

同时把 `Xjgl__Print__DefaultFontFamily` 设成 `Noto Sans CJK SC`。
