# 16 微代码：码表、码项与缓存一致性

> **对应阶段**：P1 ｜ **预计耗时**：2 小时 ｜ **产出**：一套能承载上百个国标码表、且下拉框永远不慢的码表体系

---

## 16.1 要解决的问题

学籍系统里有一大批**标准码值**：

| 码表 | 依据 | 条数 |
|---|---|---|
| 性别 | GB/T 2261.1 | 3 |
| 民族 | GB/T 3304 | 56 |
| 政治面貌 | GB/T 4762 | 13 |
| 身份证件类型 | JY/T 1001-2012 | 6 |
| 学籍状态 | 教育部学籍管理办法 | 6+ |
| 行政区划 | GB/T 2260 | 3000+ |

它们的共同特征非常鲜明：

> **读得极多，变得极少。**

一个学生列表页要翻译性别、民族、政治面貌、学籍状态四个字段；
一天几千次页面加载 = 几万次码表读取，而码表一年可能只改一两条。

**因此设计的全部要点是"读得快 + 改得对"**：

- 读：进程内缓存 + 按编码取（`items-by-code`），而不是每次查库；
- 改：改完必须**失效缓存**，否则用户看到的是旧码值。

## 16.2 表设计

```csharp
public class SysCodeCategory : FullAuditedAggregateRoot<Guid>, IXjglBusinessEntity
{
    public string Code { get; set; } = default!;       // 如 NATION
    public string Name { get; set; } = default!;       // 如 民族码
    public string? StdSource { get; set; }             // 标准依据，如 GB/T 3304

    /// <summary>是否树形（行政区划、学校类型等有层级）；树形码表按 ParentId 组织</summary>
    public bool IsTree { get; set; }

    /// <summary>系统内置：国标/行业标准定义的码表，业务上不允许改</summary>
    public bool IsSystem { get; set; }

    /// <summary>是否参与缓存（变化极少的长码表才缓存）</summary>
    public bool Cacheable { get; set; } = true;

    public bool IsEnabled { get; set; }
    public int Sort { get; set; }
    public string? Remark { get; set; }
}

public class SysCodeItem : FullAuditedAggregateRoot<Guid>, IXjglBusinessEntity
{
    public Guid CategoryId { get; set; }
    public string Code { get; set; } = default!;       // 码值，如 01
    public string Name { get; set; } = default!;       // 名称，如 汉族
    public Guid? ParentId { get; set; }                // 树形码表用
    public string? PathCode { get; set; }              // 与组织树同样的物化路径思路
    public int TreeLevel { get; set; }
    public string? StdCode { get; set; }               // 保留国标原始码值
    public int Sort { get; set; }
    public bool IsEnabled { get; set; }

    /// <summary>扩展信息（JSON 字符串）。列类型是 text 而不是 jsonb，原因见第 07 章坑 1</summary>
    public string? ExtJson { get; set; }
}
```

**`IsSystem` 是这套设计里最实用的一列**：内置码表（性别、民族…）由国家标准定义，
业务人员改了之后，上报数据就对不上国家标准了。所以服务端拒绝修改它们，
**前端也直接把编辑按钮禁掉** —— 提前拦住比让用户点了再报错体验好。

> 方案文档里还规划了 `sys_code_map`（码值映射，用于多套标准之间的对照）与
> `sys_code_rule`（码值规则校验）。**这两个表目前没有实现** —— 它们解决的是
> "上级用 A 标准、下级用 B 标准"的对接问题，属于有明确需求时再做的功能。
> 这里如实说明，避免读者以为已经具备。

## 16.3 缓存：读得快，改得对

### 读路径

```csharp
[Authorize]   // 注意：类上只要求登录 —— 下拉框人人都要用
public class CodeAppService : XjglAppService, ICodeAppService
{
    // 按类别编码取码项：前端下拉框走这个接口
    public async Task<List<CodeItemLookupDto>> GetItemsByCodeAsync(string categoryCode, bool onlyEnabled = true)
    {
        // 可缓存的码表：先查缓存，未命中再查库并回填
        ...
    }
}
```

**为什么查询接口对所有登录用户开放、只有写操作要权限**：
下拉框遍布每个业务页面，如果读码表也要 `Sys.Code.Query` 权限，
那任何没有这个权限的角色都会看到一堆空下拉框。
**码表是基础设施，不是敏感数据。**

### 写路径

```csharp
public async Task<CodeItemDto> CreateItemAsync(CreateUpdateCodeItemDto input)
{
    // 1) 内置码表不允许改
    var category = await EnsureCategoryAsync(input.CategoryId);
    if (category.IsSystem)
    {
        throw new BusinessException(XjglDomainErrorCodes.SystemCodeNotAllowedToModify)
            .WithData("reason", "系统内置码表不允许修改");
    }

    // 2) 落库
    var entity = new SysCodeItem(...);
    await _items.InsertAsync(entity, autoSave: true);

    // 3) ★ 失效缓存
    await RefreshCacheAsync();

    return ToDto(entity);
}
```

**第 3 步不能省**：不失效缓存的表现是"改完了刷新页面还是旧值"，
而管理员会以为"系统坏了"，反复改、反复不生效。

界面上还额外提供了一个**手动"刷新缓存"按钮**
（`POST /api/app/code/refresh-cache`），用于运维兜底。

## 16.4 种子数据：内置码表从哪来

`src/Xjgl.Domain/Codes/CodeDataSeedContributor.cs` 里按类别硬编码了内置码表：

```csharp
await AddAsync("SEX", "性别码", "GB/T 2261.1", 10, new[]
{
    ("1", "男"), ("2", "女"), ("0", "未知")
});

await AddAsync("ID_TYPE", "身份证件类型码", "JY/T 1001-2012", 40, new[]
{
    ("1", "居民身份证"), ("2", "军官证"), ("3", "港澳居民来往内地通行证"),
    ("4", "台湾居民来往大陆通行证"), ("5", "护照"), ("9", "其他")
});
// ... 共 132 个码类别、327 条码项（实测计数）
```

幂等逻辑与元数据种子一致：

```csharp
private async Task AddAsync(string code, string name, string? stdSource, int sort,
    (string Code, string Name)[]? items = null, bool isTree = false, bool isSystem = false)
{
    var category = await _categories.FindAsync(c => c.Code == code);

    if (category == null)
    {
        category = new SysCodeCategory(...);
        await _categories.InsertAsync(category, autoSave: true);
    }

    if (items == null || items.Length == 0) return;

    // ★ 已存在的码值跳过，不重复插入
    var existingCodes = (await _items.GetListAsync(i => i.CategoryId == category.Id))
        .Select(i => i.Code).ToHashSet(StringComparer.Ordinal);

    foreach (var (itemCode, itemName) in items)
    {
        if (existingCodes.Contains(itemCode)) continue;
        await _items.InsertAsync(new SysCodeItem(...), autoSave: true);
    }
}
```

**注意 `NATION`（民族码 56 条）与 `COUNTRY`（国别码）在种子里是"待导入"状态**：
标准原文的码值需要按教育部口径核对，硬编码一份不准确的还不如留空 + 提供导入模板。
**宁可空着，也不要塞一份似是而非的标准数据** —— 学籍数据要上报，码值错了会被上级退回。

**① 幂等**

```powershell
dotnet run --project src\Xjgl.DbMigrator 2>&1 | Select-String "完成：码类别"
dotnet run --project src\Xjgl.DbMigrator 2>&1 | Select-String "完成：码类别"
# 两次输出必须逐字一致（实测：码类别 132 个，码项 327 条）
```

**② 只返回启用项**

```powershell
GET /api/app/code/items/<categoryId>?onlyEnabled=false   # 含停用
GET /api/app/code/items/<categoryId>?onlyEnabled=true    # 只有启用
```

我在真实环境建了 2 个码项（一个停用），核对结果是：
`onlyEnabled=false` 返回 2 条、`=true` 返回 1 条 —— 过滤生效。

**③ 下拉框接口**

```powershell
GET /api/app/code/items-by-code?categoryCode=SEX&onlyEnabled=true
# 期望 3 条：1=男 / 2=女 / 0=未知
```

## 16.6 踩坑记录

### 坑 1：删码值让历史数据"翻译不出来"

学生表里存的是码值（`gender_code = '1'`），显示时才翻译成"男"。
删掉码值为 `1` 的码项后，所有历史学生的性别都显示为空 ——
但**数据并没有丢，是翻译不出来了**。

**处理**：
- 界面上明确提示"删除后历史数据无法翻译"；
- 更推荐**停用**（`IsEnabled = false`）而不是删除：下拉框不再出现，但历史仍能翻译。
  这一条直接写在了前端码项编辑框旁边的提示里。

### 坑 2：树形码表按平铺展示

行政区划、学校类型这类码表是有层级的。`asTree=false` 时后端返回平铺列表，
前端如果不用树形组件渲染，就会看到"河南省/郑州市/金水区"混在一起，看不出从属关系。

**处理**：类别上的 `IsTree` 决定前端是否用 `el-table` 的树形数据渲染
（`row-key` + `tree-props`），并且请求时传 `asTree=true` 让后端组装好层级。

### 坑 3：把码表当成业务数据改了

有人把 `STUDENT_STATUS`（学籍状态）的码值改成业务上的自定义状态，
结果上报时对不上教育部的口径。

**判断标准**：**有标准依据的（`StdSource` 非空）就是国家标准的一部分，
只能停用不能改；只有自建的业务分类才允许自由增删。**

### 坑 4：`cacheable` 的取舍

理论上所有码表都能缓存，但**高频变更的自建码表不适合缓存**：
缓存必然带来"改完不生效"的窗口。因此 `Cacheable` 做成可配置项，
默认 `true`（长码表），自建短码表可以关掉。
