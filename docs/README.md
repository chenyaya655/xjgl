## 二、设计与决策记录（`学籍管理系统-总体方案.md`）

一份持续更新的方案文档，记录**每个决定的取舍与推演**，而不是结论清单。
它的写法是"当时面对什么选择、为什么这么选、不这么选会怎样"。

结构上分两段：

- **前半**：方案本身的推演（技术选型、数据模型、权限、照片存储、部署）；
- **后半**（§16 起）：**分轮次的实施记录**，每一节都对应一批真实改动，
  并带上实测数据与踩坑过程。

> 这也是本仓库文档量偏大的原因。取舍是：**宁可文档长，也不要让下一个接手的人
> 重新踩一遍已经踩过的坑**。做政务系统的人应该能体会这一点。

## 三、从零手写教程（`learning/`）

**49 章**（另有 1 篇导航 README），按"实际建库、建表、建接口的顺序"走一遍。每章固定四段结构：

1. **要解决的问题** —— 不这么做会踩什么坑；
2. **动手步骤** —— 可以直接照抄的命令与代码；
3. **验证方法** —— 怎么确认这一步真的成了（而不是"看起来没错"）；
4. **踩坑记录** —— 我实际踩过的，以及为什么。

它面向"想自己搭一个类似系统的人"，**不是 API 手册**。
章节入口与进度表见 [`learning/README.md`](learning/README.md)。

## 关于这些文档的两点说明

1. **不含内部会话纪要**。开发过程的逐轮交接记录（含本机环境细节）按约定
   不进入公开仓库，只在维护者本机保留。
2. **开发口令是公开的**。文档里出现的 `Xjgl@Dev2026`、`1q2w3E*` 等
   都是**本地开发用的**，与实际部署无关；生产必须替换，见 [`SECURITY.md`](../SECURITY.md)。
